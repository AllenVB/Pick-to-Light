1. Yönetici Özeti ve Proje Hedefi

Operatörün ekran taramak yerine yanan ışığı takip ettiği, stoğu kendi düşen bir depo toplama sistemi.

1.1 Problem

E-ticaret depolarında sipariş hazırlama (order picking) süresinin büyük bölümü ürünü aramakla geçer. Elle yapılan toplamada üç temel sorun vardır: raf arama kaynaklı zaman kaybı, yanlış ürün/yanlış adet kaynaklı insan hatası ve stoğun anlık görülememesinden doğan "kör stok" durumu — eksik, ancak sipariş anında fark edilir.

1.2 Çözüm

Her envanter kutusunun başına bir durum LED'i ve bir onay sensörü yerleştirilir. Sisteme sipariş numarası girildiğinde yazılım, siparişteki her kalem için ilgili kutuyu bulur, stok durumunu değerlendirir ve kutunun LED'ini üç renkten biriyle yakar:

YEŞİL  Stok yeterli
Ürün rahatça verilir, sistem stoğu otomatik düşer.
SARI  Stok azaldı
Sipariş karşılanır ama kritik seviye; uyarı ve tedarik talebi üretilir.
KIRMIZI  Stok yetersiz
Alarm; kalem kilitlenir, ekrana uyarı basılır, tedarik tetiklenir.

1.3 Proje hedefi (8. hafta sonunda ulaşılacak nokta)

Sipariş numarasını gören, doğru kutuyu ışıkla gösteren, operatörün onayıyla stoğu kendi düşen, yetersiz stokta alarm veren ve tüm hareketi loglayan, en az 4 kutuluk çalışan bir fiziksel prototip + web arayüzü.

1.4 Ölçülebilir hedefler

2. Kapsam, Varsayımlar ve Kapsam Dışı

Ne yapacağız, neyi bilerek yapmıyoruz.

2.1 Kapsam içi

  • Sipariş girişi (manuel sipariş numarası + kalemleri) ve sipariş listeleme
  • Ürün, kutu ve stok envanterinin yönetimi (CRUD + sayım)
  • Sipariş numarasına göre kutu eşleştirme ve LED yakma
  • Üç renkli stok durumu kararı (yeşil / sarı / kırmızı) ve eşik yönetimi
  • Operatör teyidi sonrası otomatik ve atomik stok düşme
  • Yetersiz stokta ekran alarmı + tedarik talebi kaydı
  • Tüm stok hareketlerinin ve cihaz olaylarının loglanması

  • Çok depolu / çok lokasyonlu yapı — tek depo varsayılır
  • Rota optimizasyonu (en kısa toplama yolu hesaplama)
  • Mobil uygulama; arayüz responsive web olarak kalır
  • Bulut dağıtımı ve yüksek erişilebilirlik; sistem yerel ağda (LAN) çalışır

5.4 Örnek DDL (çekirdek tablolar)

CREATE TYPE led_rengi   AS ENUM ('YESIL','SARI','KIRMIZI');
CREATE TYPE hareket_tipi AS ENUM ('CIKIS','GIRIS','SAYIM');

CREATE TABLE urun (
  id              bigserial PRIMARY KEY,
  sku             varchar(50)  NOT NULL UNIQUE,
  ad              varchar(150) NOT NULL,
  birim_agirlik_g numeric(10,2),
  guvenlik_stogu  int NOT NULL DEFAULT 5 CHECK (guvenlik_stogu >= 0),
  olusturma       timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE kutu (
  id               bigserial PRIMARY KEY,
  kod              varchar(20) NOT NULL UNIQUE,
  urun_id          bigint REFERENCES urun(id),
  cihaz_mac        varchar(17) NOT NULL UNIQUE,
  mqtt_topic       varchar(60) NOT NULL UNIQUE,
  raf_konumu       varchar(30),
  baglanti_durumu  varchar(10) NOT NULL DEFAULT 'OFFLINE',
  son_gorulme      timestamptz
);

CREATE TABLE stok (
  kutu_id       bigint PRIMARY KEY REFERENCES kutu(id) ON DELETE CASCADE,
  adet          int NOT NULL CHECK (adet >= 0),   -- negatif stok imkânsız
  son_agirlik_g numeric(10,2),
  versiyon      int NOT NULL DEFAULT 0,
  guncelleme    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE siparis_kalemi (
  id            bigserial PRIMARY KEY,

6. Çekirdek İş Mantığı: Işık Kararı ve Atomik Stok Düşme

Projenin kalbi burasıdır. Yanlış kurgulanırsa "ışık yeşil ama kutuda ürün yok" durumu doğar.

6.1 Işık kararı

s = kutudaki mevcut stok · q = sipariş kalemi miktarı · b = ürünün güvenlik stoğu

YEŞİL
s ≥ q + b
Sipariş sonrası bile güvenlik stoğu korunuyor. Ürün verilir, stok düşer.
SARI
q ≤ s < q + b
Sipariş karşılanır fakat kritik seviyeye inilir. Uyarı + tedarik talebi.
KIRMIZI
s < q
Karşılanamaz. Kalem YETERSIZ, alarm, tedarik talebi; stok düşülmez.
// Domain/Kurallar/IsikKarari.cs — saf fonksiyon, yan etkisiz, kolay test edilir
public static LedRengi Belirle(int mevcut, int istenen, int guvenlik)
{
    if (istenen <= 0) throw new ArgumentOutOfRangeException(nameof(istenen));
    if (mevcut <  istenen)             return LedRengi.Kirmizi;
    if (mevcut <  istenen + guvenlik)  return LedRengi.Sari;
    return LedRengi.Yesil;
}

6.2 Atomik stok düşme — yarış koşulunun çözümü

Problem İki operatör aynı anda aynı kutudan toplama yaparsa: ikisi de stoğu okur (10 adet), ikisi de yeterli görür (q=6), ikisi de düşer → stok −2 olur veya biri eli boş döner. Klasik read-then-write yarış koşulu.

Çözüm: Kontrol ve düşme ayrı iki adım değil, tek bir koşullu UPDATE'tir. Veritabanı satır kilidini kendisi koyar.

-- Etkilenen satır sayısı 1 ise düşme başarılı, 0 ise stok yetersiz.
UPDATE stok
   SET adet = adet - @q,
       versiyon = versiyon + 1,
       guncelleme = now()
 WHERE kutu_id = @kutuId
   AND adet >= @q
RETURNING adet AS sonraki_adet, adet + @q AS onceki_adet;
// Infrastructure/Persistence/StokDeposu.cs
public async Task<StokDusSonucu> DusAsync(long kutuId, int q, CancellationToken ct)
{
    await using var tx = await _db.Database.BeginTransactionAsync(ct);

    var satir = await _db.Database
        .SqlQuery<StokDusSatiri>($"""...""")   // yukarıdaki UPDATE ... RETURNING
        .FirstOrDefaultAsync(ct);

    if (satir is null)                       // 0 satır → stok yetersiz
        return StokDusSonucu.Yetersiz();

    _db.StokHareketleri.Add(new StokHareketi {   // aynı transaction içinde log
        KutuId = kutuId, Tip = HareketTipi.Cikis, Miktar = q,
        OncekiAdet = satir.OncekiAdet, SonrakiAdet = satir.SonrakiAdet,
        SiparisKalemiId = kalemId, PersonelId = personelId
    });
    await _db.SaveChangesAsync(ct);
    await tx.CommitAsync(ct);
    return StokDusSonucu.Basarili(satir.SonrakiAdet);
}

Üç savunma hattı birlikte çalışır: (1) WHERE adet >= @q koşulu, (2) tablodaki CHECK (adet >= 0) kısıtı, (3) versiyon alanıyla optimistic lock. Stok hareketi logu aynı transaction'da yazılır; "düştü ama loglanmadı" durumu oluşamaz.

6.3 Ne zaman düşeceğiz? — Rezervasyon modeli kararı

SeçenekNasıl çalışırDeğerlendirme
A) Sipariş kabulünde düş SEÇİLDİSipariş başlatılırken stok atomik düşülür; LED ancak düşme başarılıysa yakılırYeşil ışık garantidir — ışık yandıysa ürün o siparişe ayrılmıştır. Kırmızı daha ışık yanmadan yakalanır. İptal durumunda iade (GIRIS) gerekir.
B) Fiziksel teyitte düşIşık yanar, operatör alır, teyit gelince düşülürFiziksel gerçeğe daha yakın; ancak iki operatör aynı anda yeşil ışık görebilir ve biri eli boş döner. Reddedildi.
Karar (Hafta-1 sunumuyla uyumlu): "Önce stoğu düş, sonra siparişi onayla" 1. Sipariş başlatılır → her kalem için koşullu UPDATE denenir.
2. Başarılı → kalem ISIK_YANDI, LED yeşil/sarı yanar, CIKIS hareketi loglanır.
3. Başarısız (s<q) → kalem YETERSIZ, LED hiç yanmaz, alarm + tedarik talebi; sipariş KILITLI veya kısmi devam.
4. Operatör teyidi geldiğinde kalem ALINDI olur — bu adım stoğu tekrar düşürmez, yalnızca fiziksel alımı doğrular.
5. Sipariş iptal edilir veya teyit zaman aşımına uğrarsa rezerve miktar GIRIS hareketiyle iade edilir.

6.4 Kutu seçim algoritması (bir ürün birden çok kutudaysa)

  1. Ürünün bağlı olduğu ONLINE kutular listelenir.
  2. Stoğu q'yu tek başına karşılayan kutular arasından en az stoğu olan seçilir (FIFO'ya yakın davranır, kutuyu boşaltarak ikmali kolaylaştırır).
  3. Hiçbir kutu tek başına yetmiyorsa: toplam stok yeterliyse kalem bölünür (iki kutudan toplama, iki LED sırayla yanar); yetmiyorsa KIRMIZI.
  4. Hiç ONLINE kutu yoksa kalem BEKLIYOR kalır, CIHAZ_OFFLINE alarmı üretilir ve arayüz manuel toplama önerir.

v1 sadeleştirmesi: kalem bölme (3. madde) opsiyoneldir, 6. haftada zaman kalırsa eklenir. Varsayılan davranış tek kutudan toplamadır.

  bağlantı dönünce sırayla gönderilir → "offline'da alınan ürün" kaybolmaz.

10.4 Firmware gereksinimleri

  • Kimlik: cihaz MAC adresi topic ve kimlik doğrulamada kullanılır; kutuId ilk kurulumda NVS'e yazılır.
  • Yanıt süresi: komut alındıktan sonra LED < 200 ms içinde yanar.
  • Miktar gösterimi: alınacak adet, LED'in o sayıda kısa yanıp sönmesiyle gösterilir (ek donanım gerektirmeyen çözüm).
  • Debounce: buton için 50 ms; çift tetiklenme firmware'de engellenir, sunucu tarafında ayrıca mesajId ile korunur.
  • Ağırlık doğrulaması: HX711 kullanılıyorsa alınan ağırlık miktar × urun.birim_agirlik_g ile ±%10 toleransla karşılaştırılır; uyuşmazsa HATA olayı gönderilir.
  • Güvenli varsayılan: MQTT bağlantısı yoksa LED yakılmaz (yanlış yönlendirme riskini ortadan kaldırır); kutu üzerinde küçük bir "bağlantı yok" göstergesi (LED kısa mavi/beyaz nabız) kullanılır.
  • OTA (opsiyonel): ArduinoOTA ile kablosuz firmware güncelleme — 7. haftada zaman kalırsa.
